# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository

## Commands (run from repo root)

```bash
npm run dev             # Vite dev server + Electron in parallel
npm run build           # tsc (electron) + vite build (renderer)
npm run electron:build  # Package distributable DMG (macOS)
npm run typecheck       # tsc --noEmit on both configs (renderer + electron)
npm run lint            # ESLint (flat config, --max-warnings 0); lint:fix to autofix
npm run format          # Prettier write; format:check to verify
npm test                # Vitest (unit tests for pure modules)
```

Unit tests (Vitest) live under `test/` and cover the pure parsing modules —
`cost-tracker`, `memory-reader`/`memory-writer`, `session-reader`,
`sessions-registry-reader`, `chat-stream`, `update-checker`, `plans-reader`,
`data-change-scope`, `session-read-cache`, `tasks-reader`, and the chat `utils`.
`session-sdk-read`/`session-sdk-cache` are auth-free **integration** tests against the
real Agent SDK (files on disk, no model turn, no API key): they pin the transcript
read path, the `dir` narrowing hint and its empty-result fallback, and the read
cache's invalidation. CI (`.github/workflows/ci.yml`) runs format:check +
typecheck + lint + test + build on every push/PR. The style gate is strict:
Prettier formatting is enforced repo-wide and `lint` runs with
`--max-warnings 0`, so a new warning fails the build — fix it or add an inline
`eslint-disable` with a reason. `typecheck` covers three projects: the renderer,
the main process, and `tsconfig.test.json` for `test/` — the suite used to be the
one part of the repo tsc never looked at.

**Renderer tests** run in jsdom against a fake preload bridge
(`test/helpers/fake-electron-api.ts`). `window.electronAPI` is the renderer's
single seam to the main process, so replacing it makes hooks and components run
unmodified with no Electron, no SDK and no `~/.claude` on disk: request/response
methods are `vi.fn()`s returning the `{ data, error }` envelope, `on*` channels
are `Channel`s a test emits on, and `Channel.listenerCount` catches
subscriptions that outlive their component. Opt in per file with a
`// @vitest-environment jsdom` docblock — the global environment stays `node` so
the ~45 main-process test files keep their startup cost. Covered so far:
`use-live-chat` (stream-envelope filtering, turn commit, permission queue,
resume seed, teardown), `use-data-changed-refetch` (debounce window, scope
union, the widen-on-unknown-payload fallback), `telemetry-report-error` (what
reaches `telemetry:trackError` and what the browser-noise filter drops first)
and `settings-cli-version` (Settings → General prints `claude --version`, never
the SDK handshake's bundled `claude_code_version`, and says so when the read
fails instead of falling back to it).
Extend the fake as tests reach further; the one cast lives at its install point.

**Do not launch the app yourself to verify UI changes** (neither `npm run dev`
nor the `run-app` skill / Playwright driver) — it doesn't work reliably in this
setup and wastes time. Verify with `npm run typecheck` + `npm run lint` + `npm
test`, adding a renderer test when the change touches hook or stream state, and
leave running the app to the user, who will check the UI manually. Visual and
layout behavior still has no automated coverage.

## Release

Before creating a GitHub Release, always run these steps **in order**:

1. `node scripts/prepare-release.js` — detects the locally installed Claude Code version and writes it into `claudeCodeVersion` in `package.json` (displayed in Settings → General → "Claude Code required")
2. Bump the app `version` field in `package.json` (semver, e.g. `2.1.1` → `2.1.2`)
3. Commit both changes together (e.g., `chore: bump to v2.1.2, claude-code 2.1.191`)
4. Create the GitHub Release with a `## Highlights` section at the top

**Binaries are built and attached by CI, not locally**: pushing the `v*` tag
(which `gh release create` does) triggers `.github/workflows/release.yml` — it
packages macOS DMG (x64 + arm64), Windows exe (windows-2022 runner) and Linux
AppImage on native runners (~9 min) and uploads all of them to the existing
Release without overwriting its notes. Don't run `npm run electron:build` or
attach assets by hand; just wait for the workflow and verify the assets landed
(`gh release view vX.Y.Z --json assets`).

**macOS signing is wired but conditional** (`docs/macos-signing.md`). The mac job
signs with a Developer ID certificate and notarizes when the repo has the five
Apple secrets, and falls back to the historical unsigned DMG when it doesn't —
so forks and this repo pre-certificate keep releasing. The build config
(`hardenedRuntime` + `build/entitlements.mac.*.plist`) is inert until an identity
exists; the entitlements are the short list a hardened Electron app needs, and
the app must stay **unsandboxed** (it reads `~/.claude`, drives arbitrary project
dirs and spawns the `claude` CLI through a pty). When a signed build ships,
three pieces of user-facing text about the quarantine workaround go stale —
README, Settings → General (`QUARANTINE_CMD`) and `UpdateBanner.tsx` — and
`electron-updater` becomes possible for the first time.

## Architecture

ClaudeLens is an Electron app that reads Claude Code's local data from `~/.claude/`.

**Main process** (`electron/main.ts`):

- Registers IPC handlers grouped by namespace: `memory:*`, `cost:*`, `claudeMd:*`, `sessions:*` (incl. `sessions:sendMessage`/`sessions:stopMessage`/`sessions:endChat` — chat runs through the **Agent SDK** in **streaming input mode**: one long-lived `ChatSession` per chat view drives a single persistent `query()` whose `prompt` is a push-generator (`modules/chat-runner.ts`), so successive turns ride the same warm session instead of re-resuming each time. `sendMessage` pushes the message into the live session when its id matches (applying `setModel`/`setPermissionMode` first), else resumes the transcript into a fresh session; `startMessage` starts a _new_ session with a **pre-generated `sessionId`** (`crypto.randomUUID`), emitting `sessions:chatStarted` immediately (no race); `stopMessage` is a native `interrupt()` (ends the turn, keeps the session warm); `endChat` disposes the session when the view unmounts. Streams over `sessions:chatChunk` (text deltas) + `sessions:chatToolActivity` (live "using tool" indicator: tool-input generation start + `tool_progress` heartbeats) + `sessions:chatMessage` (each fully-formed assistant/tool-result message as the SDK emits it, so the renderer builds the live turn — tools included — straight from the stream, not from a mid-stream disk re-read) + `chatDone` (per-turn end, carrying the SDK's `ChatTurnSummary` — cost/tokens/model read from the `result`, so the live chat shows running metadata without touching disk) / `chatError`. **Every stream payload is an envelope tagged with the producing `sessionId`** (`Chat*Event` in `electron/shared/chat-types.ts` — the single type definition shared with the renderer, re-exported by `src/types.ts`; permission requests carry the id too), so the renderer's `useLiveChat` drops stale events from a superseded session instead of trusting arrival order. Tool approvals go through the SDK's `canUseTool`: a non-auto-approved tool fires `sessions:permissionRequest` → the renderer's Allow/Always/Deny dialog (requests are **queued** renderer-side — concurrent `canUseTool` calls, e.g. parallel read-only tools, are answered one at a time; `AskUserQuestion` gets a dedicated answer form returning `{ questions, answers }` in the allowed input) → `sessions:permissionResponse` resolves the SDK's pending `PermissionResult` (`pendingPermissions` Map; `stopMessage`/`endChat`/supersede deny all pending). One `ChatSession` in flight at a time; if the live query dies on its own (fatal stream error — not a deliberate dispose) the main emits a final `chatDone` so the composer doesn't stay stuck on "Stop"), `rules:*`, `tasks:*`, `plans:*`, `workflows:*`, `teams:*`, `agents:*`, `skills:*`, `plugins:*` (installed plugins + their skills/agents/commands), `mcp:*`, `projects:*` (duplicate detect/merge), `live:*` (Live Monitor), `ai:*`, `export:*`, `markdownFile:*`, `settings:*`, `config:*` (effective config via Agent SDK), `telemetry:*` (anonymous usage telemetry — `telemetry:isEnabled`/`telemetry:setEnabled` opt-out toggle + `telemetry:track` for renderer-fired feature events), `updates:*` (`updates:check` — GitHub-releases update check, see `modules/update-checker.ts`), `clipboard:*` (`clipboard:readText`/`writeText` via Electron's own `clipboard` module — the packaged renderer runs from `file://`, where `navigator.clipboard`'s read path needs a permission the app never grants; used only by the terminal pane's Windows/Linux copy-paste bindings)
- Watches `~/.claude/projects/`, `~/.claude/tasks/`, `~/.claude/plans/`, `~/.claude/teams/`, `~/.claude/workflows/`, each known project's `.claude/workflows/` and `~/.claude/plugins/installed_plugins.json` with chokidar (**depth 5** — depth 3 would stop at `{hash}/{sessionId}/subagents/` and never see the workflow sub-agent transcripts nested one level further, at `subagents/workflows/<runId>/agent-*.jsonl`; team inboxes are `ignored`); emits `data:changed` to renderer on any change, **carrying the namespaces the changed path can affect** (`modules/data-change-scope.ts` — a pure path classifier; `null` = "unknown", which the renderer must read as "invalidate everything"). The renderer unions the scopes across its debounce window and invalidates only those query keys, so a transcript append during a live chat no longer re-reads skills/agents/plugins/MCP (#148). A separate chokidar watch on `~/.claude/sessions/` (the live-session registry, rewritten on session status transitions) pushes the fresh `ActiveSession[]` over its own `live:activeSessions` channel (debounced read) instead of `data:changed`, so registry churn doesn't invalidate every React Query cache
- Serializes `Map` → plain object before IPC (Maps are not transferable)

**Preload** (`electron/preload.ts`):

- Exposes `window.electronAPI` via `contextBridge` with context isolation
- `onDataChanged(callback)` lets the renderer subscribe to file watcher events

**Backend modules** (`electron/modules/`) — pure functions except `memory-writer.ts`:

- `memory-reader.ts` — parses `MEMORY.md` index and topic `.md` files; reads `type` and `originSessionId` from the topic frontmatter (flat or nested under `metadata:`), falling back to filename-prefix inference for the type (`feedback_`, `project_`, `reference_`; default `user`). All I/O is **async and safe-fs'd**: one directory listing decides everything (whether `MEMORY.md` exists included) and each file is read **once** through `readTextFile` — the index's frontmatter and the `topics` body map share that read, and the frontmatter is YAML-parsed once per file. The sync reads it replaced were a main-process hazard, not just a cost: the project-level dir (`{realPath}/.claude/memory/`) is a real project path, so a dataless iCloud file froze the whole app (see the safe-fs rationale). The cost is paid often — a transcript append carries the `memory` scope, so a live chat re-invokes `memory:getProject` on every watcher burst. Missing/unreadable topics degrade instead of throwing (the index line survives with the filename-prefix type); an index link that escapes the memory dir is never opened. Pure `parseIndexLines` is unit-tested (`test/memory.test.ts`)
- `memory-writer.ts` — creates/updates/deletes topic files, keeps `MEMORY.md` in sync; normalizes accented chars in filenames
- `cost-tracker.ts` — parses `.jsonl` session files; hardcoded pricing table per model with fuzzy fallback to Sonnet. Rates are verified against the official pricing page and stamped in `PRICING_LAST_UPDATED` (bump it when you touch them); `cacheWrite` is the **5-minute** write rate, because a transcript records one `cache_creation_input_tokens` figure and never says which TTL produced it. Model ids are matched exactly, then again with an `-YYYYMMDD` release stamp stripped, then by family — the fuzzy anchors must point at the CURRENT generation of each family, since anchoring `opus` on a retired model is what charged every Opus 4.5+ session 3x its real price. A model whose published rate changes on a date lives in `SCHEDULED` instead (Sonnet 5's introductory pricing): `getPricing(model, at)` resolves it against the session's own timestamp, so historical cost stays correct across a cutover. Parses are served by an append-only incremental cache (mtime+size key), keyed **dir → file** so it can be pruned: every scan's glob is the live set of its directory, so `findSessionFiles` evicts transcripts that vanished (in-app session delete, retention) and `calculateCostSummary` evicts whole projects that were deleted or merged away. Without pruning an entry survived for the life of the process — nothing re-stats a deleted file — holding its `seenUsage` set (one string per assistant turn) with it. `getParseStats()` (incl. `cachedFiles`/`evictions`) / `resetParseCache()` expose the cache for tests
- `claude-md-reader.ts` — reads CLAUDE.md hierarchy: global → project → local (`CLAUDE.local.md`) → subdir (`.claude/CLAUDE.md`)
- `rules-reader.ts` — reads conditional rules from `.claude/rules/**/*.md`; extracts `paths` from YAML frontmatter
- `session-reader.ts` — parses JSONL chat sessions; skips meta/sidechain lines (unless `includeSidechain` is set, used to read sub-agent transcripts); normalizes content (string or block array); drops the local-command placeholder assistant message (`isPlaceholderNote`: a lone text block exactly `"No response requested."`, the junk Claude Code persists for `/context`/`/usage`/… while discarding the real output) — applied in both `readChatSession` and `mapSdkMessageToChat`. The SDK-backed readers (`readChatSessionViaSdk`, `readSubagentTranscriptViaSdk`) take an optional `SessionSource` (`{ projectDir, cwd }`) that makes them **change-stamped and project-scoped** — see `session-read-cache.ts`. `cwd` is the SDK's `dir` hint and must be the project's **real cwd** (`resolveRealPath`), NOT `~/.claude/projects/<hash>`: the SDK answers a wrong `dir` with an empty array rather than an error, so a scoped read that comes back empty **retries unscoped** — the hint can only save work, never hide a transcript. The retry is skipped only on **observed** evidence (`canTrustEmptyScoped`): a scoped read for that exact cwd already returned results, _and_ the source is fingerprinted under `projectDir`. That matters because empty is the NORMAL answer for `listSubagents` (most sessions dispatch nothing), and an unconditional retry would run the cross-project scan on every flush of a live session — the very cost the cache exists to remove. The check is deliberately empirical, not derived: comparing `pathToHash(cwd)` to the project dir name would bake in Claude Code's folder-naming rule (both `/` and `.` collapse to `-`), and being wrong there would hide a transcript. `getSessionReadCacheStats().unscopedRetries` counts the fallbacks
- `session-read-cache.ts` — the mtime+size guard in front of the SDK-backed session readers. Those re-parse an ENTIRE transcript per call and the renderer re-invokes them on every `data:changed` burst (scope `sessions` invalidates the `sessions:chat` key **prefix**, so an append in one session — or in a sub-agent sidecar — re-read every other session too). Measured on a 4.3 MB transcript + 6 sub-agents with a 150-project registry: one renderer flush (`sessions:getChat` + `sessions:getSubagents`) went **287 ms → 1.2 ms** when nothing changed, and **→ 44 ms** when the transcript genuinely grew. `fileStamp`/`treeStamp` fingerprint the sources (the tree walk is recursive — workflow sub-agents nest under `subagents/workflows/<runId>/` — and covers `.meta.json` sidecars, which carry the `toolUseId` the SDK turns into `parent_tool_use_id`); `StampCache` serves the previous value while the fingerprint holds, coalesces concurrent loads, and is LRU-bounded because the values are whole transcripts. A `null` stamp (source not locatable) **disables caching for that call** rather than guessing — counted as `uncacheable`, kept apart from `misses` (a miss can become a hit, an uncacheable read never will) and from `coalesced` (a caller that joined a load already in flight). Same append-only contract as the `cost-tracker`/`plans-reader` caches — but here the parsing lives inside the SDK, so only the whole call can be skipped, never part of it
- `subagents-reader.ts` — reads the per-session sub-agent transcripts Claude Code stores in `{sessionId}/subagents/agent-*.jsonl` (sidechain lines); returns metadata (`agentId`, `firstPrompt`, start/end, message count). The renderer correlates each to its `Task`/`Agent` dispatch by prompt prefix (`firstPrompt`), since the file only carries a codename `slug`, not the `subagent_type`. The dispatch prompt map is built from the **already-mapped** parent transcript (`readChatSessionViaSdk`), so `sessions:getSubagents` shares that cached read instead of parsing the same multi-MB file a second time on every flush. Change-stamped on the parent transcript **and** the whole `subagents/` tree — a new dispatch upstream and a teammate's own append both have to invalidate it
- `session-files.ts` — `listProjectSessionFiles(projectPath, onScan?)`: the one enumerator of a project's transcripts, from the **two** native layouts (`<hash>/sessions/*.jsonl` when that dir exists and is non-empty, else `<hash>/*.jsonl`). Non-recursive on purpose — `**/*.jsonl` would also match the `subagents/` sidecars (#95). `onScan` fires once per directory actually globbed, with that directory's live file list, which is the pruning point for the incremental caches of `cost-tracker` and `plans-reader`. It exists because the probe used to be copy-pasted: `tasks-reader` had the copy that read the project root only, so **every `sessions/`-layout project reported zero tasks** — empty subtab, 0 badge, empty Mission Control TASKS island — with the task folders sitting on disk and nothing logged
- `tasks-reader.ts` — reads tasks Claude creates during sessions from `~/.claude/tasks/{sessionUUID}/*.json`; maps each session UUID (the project's `.jsonl` filename, via `listProjectSessionFiles`) back to the project and groups tasks per session. Lists the tasks dir **once** and intersects with the project's session ids: the previous per-session `glob` probed `~/.claude/tasks/<id>/` once for every transcript in the project — hundreds of probes, nearly all against folders that don't exist, on a query mounted by every project view and by Mission Control
- `session-deleter.ts` — enumerates a session's on-disk artifacts (`getSessionArtifacts`: transcript `.jsonl`, sidecar `subagents/` dir, `~/.claude/tasks/{sessionId}/`, and referenced global plan files with a per-project reference count) for the delete-confirmation dialog, then deletes the user-selected paths (`deleteSessionArtifacts`), refusing any path outside `~/.claude`. Backs the `sessions:getArtifacts` / `sessions:deleteSession` IPC handlers; Claude Code has no official session-delete command (only `cleanupPeriodDays` retention)
- `teams-reader.ts` — reads Claude Code 2.x **agent teams** (in-process teammates coordinated by a team-lead). Source of truth = teammate transcripts in `{sessionId}/subagents/agent-a<name>-*.jsonl` + sidecar `.meta.json` (`taskKind: "in_process_teammate"`, `teamName`); the global registry `~/.claude/teams/<teamName>/config.json` only _enriches_ (prompts, joinedAt, members that never ran) because it is stale-prone: killed lead sessions leave members behind, every session eagerly creates a lead-only dir, and `leadSessionId` goes stale when the lead session rotates ids on resume (transcripts anchor the team to the right sessions). The sibling `inboxes/*.json` are transient message queues (drained in seconds — no history; excluded from the chokidar watch via `ignored`). `getTeamDetail` additionally parses each member transcript (`scanMemberTranscript`) into the team conversation timeline (`TeamEvent[]`: inbound `<teammate-message>` = dispatch/follow-up, outbound `SendMessage` tool calls = reports; idle notifications dropped, `to:"main"` normalized to `team-lead`) and per-member metrics (messages, tool calls, usage tokens). The numeric metrics are also rolled up to the list (`TeamSummary.memberTokens`/`totalTokens`/`messageCount`, feeding the slab cards' token-distribution footer) through an mtime-keyed per-transcript cache (cost-tracker pattern — watcher churn never re-parses an unchanged transcript; a detail read warms it); the conversation events stay detail-only. `TeamSummary` carries `leadSessionIdFromConfig` (promoted from detail so list-level liveness matches `isTeamLive` exactly). Backs `teams:getByProject`/`teams:getDetail`; UI in `src/components/project/teams/` (standalone subtab, cards grouped under their anchor session — the one `team.filename` points to — like Tasks/Plans) **plus** a **session-scoped** TEAMS species in Mission Control's event feed (`terminal/MissionRail.tsx` — only the focused session's teams, matched against the whole rotated `sessionIds` array + the stale-prone config lead id as secondary signal; the TEAMS filter pill shows whenever the project has teams at all, with an explicit "No teams in this session" state behind it; rows carry the honest LEAD-LIVE/ENDED/HISTORICAL status + `quiet Nm` stuck signal and float to the top of the feed while the lead is alive; a row click hosts the existing `TeamDetailView` in the terminal-preserving overlay)
- `plans-reader.ts` — reads plan-mode plans: scans the project's session `.jsonl` for `plan_mode`/`plan_mode_exit` attachments (carrying `planFilePath`), dedupes per file (approved > proposed), then reads the markdown from the global `~/.claude/plans/*.md`; groups per session, flags missing files as deleted. Parsing is split into a pure `extractPlanRefs(raw)` and a cached async `readPlanRefs(path)` backed by the **same append-only incremental cache as `cost-tracker`** (mtime+size key; unchanged file = zero I/O, grown file = tail-only read, trailing partial line kept as a `Buffer` so a multi-byte char is never decoded mid-sequence; entries are keyed **dir → file** so each scan can evict the transcripts that have since disappeared — the scan's own glob is that directory's live set). Without it the Plans count badge — mounted on _every_ project view — re-read every transcript in the project synchronously on each watcher burst: ~350 ms of blocked main process per flush on a 92 MB history (#148). `getPlanRefStats()`/`resetPlanRefCache()` expose the cache for tests. `session-deleter.ts` shares the same cached reader. Also surfaces **unlinked plans** (`getUnlinkedPlans`, backing `plans:getUnlinked` — #154): the `*.md` in `~/.claude/plans` that no attachment references at all, i.e. plans written straight into the dir without passing through native plan mode, which the reference-driven model made invisible. "Unlinked" is deliberately computed over the **whole install**, not the open project: the plans dir is global, so a per-project subtraction would parade every other project's plans as orphans. The extra cost is one pass over all `projects/*/` — absorbed by the same incremental cache (an unchanged transcript costs one `stat`) — and it is skipped entirely when the plans dir holds no candidates. Their `status` is `'unlinked'` (a third `PlanStatus`, kept apart from the attachment-only `PlanRefStatus`), `exists` is always true (the "deleted" state can't apply), and `timestamp` falls back to file mtime, so the detail view labels it "Modified", not "Created". Session enumeration for both entry points goes through one `sessionFilesIn` mirroring `cost-tracker`'s `findSessionFiles` (`<hash>/sessions/*.jsonl` when present, else `<hash>/*.jsonl`): reading a single location would report every plan of a `sessions/`-layout project as unlinked
- `agents-reader.ts` / `agents-writer.ts` — read/create global & project agents (`.claude/agents/**/*.md`); writer creates agent files and dispatches/attaches/respawns/stops background agents
- `skills-reader.ts` / `skills-writer.ts` — read/create global & project skills (`.claude/skills/<name>/SKILL.md`); the reader exports `parseSkillMarkdown`/`readSkillsFromDir` (reused by `plugins-reader`) and the `Skill.scope` includes `'plugin'`
- `plugins-reader.ts` — reads user-scoped plugins installed under `~/.claude/plugins/` (source of truth `installed_plugins.json` + `known_marketplaces.json`, manifest from each plugin's `.claude-plugin/plugin.json`). For each plugin enumerates the components it provides at the plugin root — `skills/*/SKILL.md`, `agents/*.md`, `commands/*.md` (reusing `readSkillsFromDir`/`readAgentsFromDir` with scope `'plugin'`) — but NOT agents nested inside a skill (`skills/<skill>/agents/*.md`, internal helpers). Project-scoped plugin installs are excluded (the section is global). Backs `plugins:getAll`
- `mcp-reader.ts` — reads the MCP servers Claude Code knows about, from **two** sources: the **live list** (`claude mcp list` via `execClaude`, the official non-interactive command behind the same health check `/mcp` runs) decides _which_ servers exist and their status; `~/.claude.json` contributes only the **per-project toggles** (`disabledMcpServers`) and any local stdio config (also read from `~/.claude/settings.json`, plus `mcp-needs-auth-cache.json` for the auth flag). **`claudeAiMcpEverConnected` must never drive the list**: it is an append-only cache of every claude.ai connector ever seen — disconnecting one from the web never removes its name and newly connected ones never get added (that field is what made the UI show connectors `/mcp` doesn't know, e.g. `claude.ai Synthesize Bio`); it now only _labels_ the on-disk leftovers, surfaced as a separate `unlistedServers` group (status `unlisted`, never "removed"). **The live list is volatile** — consecutive runs minutes apart returned 11 then 3 connectors, `claude mcp get` agreeing with each — so the reader caches it for 60s, exposes `probe.observedAt` (the UI stamps the read time and says the reading can change), and treats absence as "not in this list", not as deletion. The Agent SDK `system/init` `mcp_servers` list was tried and rejected: it is cwd-scoped (an untrusted dir — usually `~` — reports nothing) and came back empty on 3 of 4 probes of the same trusted project. Pure `parseMcpList`/`buildMcpData` are unit-tested (`test/mcp-reader.test.ts`)
- `studio-compiler.ts` / `studio-script.ts` / `studio-reader.ts` / `studio-writer.ts` — **Agent Studio** is a visual projection/editor for native Claude Code workflow scripts; the native `.js` files are the **only source of truth** (no ClaudeLens manifest or shadow blueprint). The library scans **both native locations** Claude Code resolves workflows from: the global `~/.claude/workflows/` and each known project's local `.claude/workflows/` (project cwds discovered from `~/.claude/projects` via `resolveRealPath`; `discoverProjectsWithWorkflows` doubles as the allowlist for project-scoped write IPC — an unknown `projectPath` is rejected). Summaries/details carry `scope`/`projectPath`, and read/save/delete/writeScript all take an optional `projectPath` that targets the project dir instead of the global one (Studio create stays global). `studio-script.ts` parses the script into the blueprint **node model**: each phase holds an ordered list of nodes — structured `step` (agent(), incl. `schema`/`isolation`/dynamic template labels/preserved `resultVar`), `parallel`, `pipeline` (verbatim items expression + agent/code stages), `log`, and verbatim `code` nodes for every other top-level statement (source slice, re-emitted byte-for-byte with leading comments). Statements before the first `phase()` land in `preamble`; literal unknown meta keys / phase-meta keys and trailing comments are preserved (`metaExtras`/`metaExtra`/`header`/`trailer`). `structured` is false on syntax errors **and on dynamic `meta` declarations** (identifiers, spreads, computed keys or sibling declarators), which stay source-only so a visual save can never erase native JavaScript; arbitrary JS outside `meta` keeps Brief/Flow/Canvas enabled (badge HYBRID vs VISUAL via `codeNodeCount`). Unknown `${expr}` prompt interpolations stay live in hybrid blueprints (escaped to text in pure ones). Visual Save compiles back to the same `.js` (round-trip is semantically lossless; `saveBlueprint` acorn-checks the compiled output before writing); Source Save writes it verbatim. The compiler is pure and unit-tested (`test/studio-compiler.test.ts`; parser/IO/round-trip in `test/studio-io.test.ts`). Chokidar watches `WORKFLOWS_DIR` plus every known project's workflow target (including directories not created yet), and dynamically adds/removes targets as the project registry changes. Visual and Source saves carry their original source snapshot; the writer rejects stale saves instead of overwriting an external edit. The editor also guards Back/window unload while either draft is dirty.
- `update-checker.ts` — checks the GitHub releases API (`releases/latest` of `giulio333/ClaudeLens`) for a version newer than the running one; pure `parseLatestRelease` + a Node-`https` fetch (same Keychain rationale as telemetry). `compareVersions` lives in **`electron/shared/version-compare.ts`** and is re-exported here: Settings → General needs the same semver comparison to judge the installed Claude Code against `claudeCodeVersion`, and importing this module from the renderer would drag the `https` fetch path into the bundle for one pure function. **No auto-install by design**: the app ships unsigned, so Squirrel.Mac would refuse it and a silently swapped bundle would land quarantined anyway — updating stays a manual download from the release page. Backs `updates:check` (checked once per launch by the renderer). The _installed_ Claude Code is a separate read — `updates:claudeCodeVersion` → `readInstalledClaudeVersion(env)` in `modules/claude-cli.ts` (`claude --version` parsed by `parseClaudeCliVersion` here). That function takes **no executable on purpose**: every other CLI call in the packaged app passes `resolveClaudeExecutablePath()`, the asar-unpacked binary the _SDK_ needs, and asking that one `--version` reports the CLI ClaudeLens ships (SDK 0.3.220 → "2.1.220") — it told a user on 2.1.232 they were on 2.1.220, and only on a packaged build, since in dev the resolver returns undefined and the PATH CLI answers. Unknown stays unknown ("not found in PATH"); never fall back to the bundled number. The UI is a passive bottom-left notice (`src/components/UpdateBanner.tsx`, per-version skip persisted as `cl-update-skipped-version` in prefs) plus an Updates block in Settings → General with "Check now" and the macOS quarantine-clearing command (copy button)
- `config-reader.ts` — reads the _effective_ Claude Code config via the official `@anthropic-ai/claude-agent-sdk` (ESM, dynamic import): `resolveSettings()` for the merged settings cascade + provenance (no spawn), and the `system/init` message of a one-turn `query()` (aborted before any model turn) for runtime info (resolved model, live MCP status, tools, skills, agents, slash commands, version)
- `chat-stream.ts` — pure helpers for translating the SDK message stream into chat events (`summarizeResult`, `noteMessage`/`compactBoundaryNote`, `isPromptEcho`, `isSubagentTraffic`), extracted from `chat-runner` so the translation rules are unit-testable (`test/chat-stream.test.ts`)
- `chat-runner.ts` — exposes **`ChatSession`**, a long-lived chat session backed by a single Agent SDK `query()` (ESM dynamic import) in **streaming input mode** instead of spawning `claude -p` or opening a one-shot query per turn. The `prompt` is a push-generator (a queue + resolver): `send(text)` enqueues an `SDKUserMessage` and wakes the generator, so every turn rides the SAME query — the session context stays warm (no per-turn re-resume) and the SDK's control requests are available: `interrupt()` (Stop the turn, keep the session), `setModel()`/`setPermissionMode()` mid-session, `dispose()` (abort + close the generator). Persists to the same `~/.claude/projects/<hash>/<id>.jsonl` (interchangeable with the terminal) **and** requests tool approvals interactively via `canUseTool`. The consume loop translates the SDK message stream into flat `onStarted`/`onChunk` (text deltas)/`onToolActivity` (live tool indicator: `content_block_start` of a tool_use — the model is writing the tool's input — plus `tool_progress` execution heartbeats with elapsed seconds)/`onMessage` (each fully-formed assistant or tool_result-bearing user message, mapped via `session-reader`'s shared `mapSdkMessageToChat`; skips the user message that merely echoes the prompt — the renderer already shows that optimistically)/`onError`/`onTurnEnd` (the SDK `result` — per-turn end, the session lives on; carries a `ChatTurnSummary` of cost/tokens/model read defensively from the result via `summarizeResult`)/`onClosed` (the query ended) callbacks; **sub-agent traffic is dropped** (any message or stream event with `parent_tool_use_id` set — the SDK forwards a Task subagent's tool_use/tool_result into the main stream; the live turn shows the main conversation only, matching the persisted transcript that skips sidechain lines); the SDK types are derived from the dynamic `import()` (no top-level `import type`, which the CJS build can't resolve). Also surfaces **slash-command output that carries no model turn**: a `system`/`compact_boundary` event (from `/compact`) and the final `result` text when no assistant message ran are emitted as synthetic assistant "note" messages via `onMessage` (`noteMessage`, marked `model: '<synthetic>'`). Local info commands like `/context`/`/usage` already arrive as their own `<synthetic>`-model assistant message (the real output) — but Claude Code **never persists it** (disk gets only the `"No response requested."` placeholder, filtered by `session-reader`), so the live chat (`LiveChatView`) keeps the `<synthetic>` output on screen by appending it to its in-memory stream transcript like any other message — never re-reading disk (`ChatView` is now a read-only disk viewer; the live SDK chat is a separate stream-only view). Slash commands run **natively** — the SDK executes a `/command` passed in the prompt string, no extra dispatch path. Backs `sessions:sendMessage` (push or resume) / `sessions:startMessage` (new, pre-generated `sessionId`) / `sessions:stopMessage` (interrupt) / `sessions:endChat` (dispose)
- `sessions-registry-reader.ts` — discovers **active** Claude Code sessions from the native registry Claude Code 2.x writes at `~/.claude/sessions/<pid>.json` (pid, `sessionId`, cwd, `status` busy/waiting + `waitingFor`, `startedAt`, `updatedAt`). **`updatedAt` is NOT a periodic heartbeat** (verified live on 2.1.198): the CLI rewrites the file only on status transitions, so a session mid-turn (or parked in waiting) can be minutes/hours past it — never gate liveness on it. Undocumented internal format → defensive field validation; stale files from crashed sessions are dropped via a pid-liveness probe (`process.kill(pid, 0)`) plus a **pid-reuse guard**: one `ps -o pid=,args=` call over the surviving pids must show each still runs a claude CLI (the registry is keyed by pid, so a live claude pid can only be the entry's own process; on Windows, where `ps` is unavailable, the pid probe alone decides). Non-`cli` entrypoints (SDK-spawned sessions, e.g. ClaudeLens' own chat) are excluded. Cross-platform (plain JSON reads, works on Windows). Falls back to `process-scanner.ts` only when the registry has **no files at all** (CLI < 2.x) — a populated dir whose entries all filtered out means "nothing live", not "guess with the scanner" (scanner entries carry no `sessionId` and would poison consumers matching on it). Note: the Agent SDK itself has **no** API to discover external running sessions — its `listSessions`/`getSessionInfo` only read saved transcripts
- `live-monitor.ts` — tails a session transcript in real time (ESM-only chokidar via dynamic import); given a `sessionId` (from the registry) it tails that exact `.jsonl`, else falls back to the most-recent file by mtime; `process-scanner.ts` enumerates live `claude` processes via `ps`+`lsof`/`/proc` (legacy fallback, returns `[]` on Windows); `bg-sessions-reader.ts` reads background agent sessions
- `telemetry.ts` — anonymous, opt-out usage telemetry to Aptabase. Events: `app_started` (launch), `app_exited` (quit, with `duration_seconds`), and renderer-fired feature events (`view_opened {view}` on every navigation, `chat_started`, `export_done {format}`, `terminal_opened`, `session_deleted`) — names + fixed enum/number props only, never `~/.claude` content. Anonymous system props (app version, OS name/version, locale, Chromium version, a rotating session id — no persistent user id) are attached to each, POSTed to the EU ingest API (`eu.aptabase.com/api/v0/event`, selected by the `A-EU-` app-key prefix). Renderer events go through `telemetry:track` (preload → `src/lib/telemetry.ts` helper), sanitized main-side (event-name regex, ≤10 props, string/number only, strings capped). `app_exited` is sent on `before-quit` (deferred once via `preventDefault`, `trackExit()` awaits the POST with a 2s cap so quit isn't blocked). **Deliberately does NOT use the `@aptabase/electron` SDK**: that SDK sends via `electron.net`, whose first request makes Chromium init its os_crypt cookie store → a macOS **Keychain "Safe Storage" prompt at launch** (worse on unsigned builds, which is how ClaudeLens ships). Instead we POST with Node's `https` (never touches Chromium/Keychain) — the payload mirrors the Aptabase ingest format. `track()` is gated behind the opt-out flag (`enabled`), so opting out means zero egress and the toggle is instant/restart-free. The flag persists in `~/.claudelens/preferences.json` (key `cl-telemetry-enabled`, default ON) via `prefs-store`; `isTelemetryEnabled`/`setTelemetryEnabled` back the `telemetry:*` IPC and the Settings → Privacy tab. `initTelemetry()` + `track('app_started')` run inside `app.whenReady()`. `isDebug: !app.isPackaged` routes dev runs to Aptabase's debug bucket. Disclosure lives in `PRIVACY.md` + README + the in-app panel. Disabled in `SCREENSHOT_MODE`. **Error reporting** rides the same module and the same opt-out flag, on Aptabase's second (beta) endpoint `POST /api/v0/error` — one report per request, `202` on success, `403` = monthly quota exhausted and explicitly **not** retryable (so `sendError` latches off for the run; it also dedupes by `type|message` and caps at 20 reports per run, because a throwing render loop would otherwise spend the quota by itself). Sources: `process.on('uncaughtExceptionMonitor')` in the main (chosen over `uncaughtException` because it observes **without** swallowing — Node still prints and exits, so registering it changes no behavior; an unhandled rejection arrives here too via Node's default `throw` mode, which is why no `unhandledRejection` listener is registered — adding one would silently make rejections non-fatal), `app.on('render-process-gone')` (minus `clean-exit`, the normal teardown), and renderer-side `window` `error`/`unhandledrejection` + `ErrorBoundary.componentDidCatch` through `telemetry:trackError`. The renderer drops **browser noise** before the IPC hop (`isBenignBrowserNoise` in `src/lib/telemetry.ts`): `ResizeObserver loop completed with undelivered notifications` (and its older `loop limit exceeded` wording) is not an exception but Chromium saying a resize callback needed one more frame to settle — the normal case here, since the windowed transcript re-measures every row through a ResizeObserver and `TerminalPane` refits xterm from another, and likelier on Windows, where scrollbars take space instead of overlaying. It arrives with no `error` object, hence **no stack**, so the report names no frame to look at; with the quota capped and latched off on a 403, letting it through would spend it on the one message we already know we would not act on. Wired filter covered by `test/telemetry-report-error.test.ts`. A fatal error kills the process before an async POST can leave, so `queueFatalError` writes the report **synchronously** to `~/.claudelens/pending-error.json` and `flushPendingError()` sends it on the next launch (deleting it first — never retried twice). **The scrubber is the load-bearing part**: messages and stacks are the one payload not anonymous by construction (`ENOENT: open '/Users/anna/Projects/acme'` carries a username and a project name), so everything passes through the pure `electron/shared/error-redact.ts` — absolute paths under `app.getAppPath()` keep their suffix as `<app>/…` (our own frames, the useful part), every other path collapses to `<path>`, the username is replaced with `<user>` even outside a path, and fields are capped at the API's limits. Unit-tested in `test/error-redact.test.ts`

## Key conventions

**IPC result shape:** every handler returns `{ data: T | null, error: string | null }`. Renderer unwraps with `unwrap()` in `useIPC.ts`.

**Project identity:** data lives in `~/.claude/projects/{hash}/` where `hash` = absolute path with `/` → `-` (e.g. `/Users/foo/bar` → `-Users-foo-bar`). Conversion in `electron/utils.ts`.

**Memory format:** topic files use YAML frontmatter (`name`, `description`, `type`) + markdown body. `MEMORY.md` index lines: `- [filename.md](filename.md) — description`.

**Two tsconfigs:**

- `tsconfig.json` — renderer (ESNext modules, DOM types, JSX)
- `tsconfig.electron.json` — main + preload (CommonJS, no DOM)

**Build outputs:**

- `dist/` — Vite bundle (React SPA)
- `dist-electron/` — tsc output (main.js, preload.js, modules/)
